Two defects that the counters added in v1.3.4 exposed on their first boot, on a controller that
was otherwise answering normally: six lost frames, and `Position source: Time-based estimation`
where the previous boot had said `Encoder (primary)`.

## Fixed

- **The boot burst overflowed the transmit queue.** The cover init steps, every register sensor's
  first poll and the restored template numbers all queue within a second, while the bus drains
  one frame per ~200 ms. Every send path called `write(&packet, 0)`, so it never waited: past the
  queue depth the frame was dropped, which is what the new counter caught (six frames on the
  first boot with v1.3.4). The queue is now 64 deep, and a send waits up to 30 ms for a slot
  before it gives up.
- **A missed position reply could disable encoder tracking for days.** The periodic status
  refresh asked for the position only when `has_encoder_` was already true, and the init sequence
  never requested the current position at all. So a single lost reply at boot left the cover on
  time-based estimation until the gate happened to move, because nothing would ever ask again.
  The init sequence now requests the position, and the periodic refresh no longer gates it on
  prior detection - a missed reply corrects itself within 15 s.

## Diagnostics

- Drop counters are split by cause: `get_tx_dropped()` counts frames lost with the queue full,
  `get_tx_not_ready()` counts frames sent before the bus component's `setup()` created the
  queues. No send path escapes the accounting any more: discovery and the identity requests went
  through a bare `write()` before.
- `Encoder support detected (position N), tracking from the encoder` is logged when the encoder
  is first seen. `dump_config` prints the position source at boot, before any reply can have
  arrived, so that line alone could not tell an encoder controller from a time-based one - which
  is exactly how the second defect stayed hidden.

## Watching it

`Bus frames discarded` should stay at 0, `Bus frames dropped (TX queue full)` should stay at 0
from the first boot with this release, and `Bus packets received` should climb. If the position
source matters to you, the log line above confirms encoder tracking without having to move the
gate.
